# makeitMD: audit and development update

Reviewed on 2026-10-20. Source audit started at `2bcc9dc`; development changes
are based on `dev`, including the existing `36a7b0b` documentation-output ignore
commit. This is a source and local verification report, not a production health
check or a release approval.

## Prepared in dev

- Private-chat text documents enter the existing conversion and rich-reply
  pipeline. `.md`, `.txt`, `.markdown`, `.csv`, `.json`, `.tex`, extensionless
  files and other UTF-8 text are accepted by checked contents. Accepting a
  filename does not convert its document format.
- The download budget is 128 KiB, enforced against metadata and the actual
  stream. The total getFile/download budget is 15 seconds. Transient stream
  errors retry up to three times, respecting `retry_after`.
- Strict UTF-8, optional initial BOM, original CRLF and whitespace preservation.
  Binary signatures, NUL, unexpected control characters and empty input are
  rejected with a localized explanation. PDF, Word and archives are not
  extracted. Filename and reported MIME are not trusted as proof of text.
- Captions do not enter the source. Documents are never joined with nearby
  pastes. `/start` inside a file is source, not a command. Groups do not trigger
  a download or database write.
- A random private temporary directory holds downloads and is removed after
  success or failure. No filename, source, caption or download error body is
  logged. Accepted source and document metadata use existing retention;
  rejected files do not create conversion rows.
- A terminal conversion is checked before downloading a replayed document.
  Successful file submissions produce the same native reply as pasted text.
- How it works now explains files, formulas and Telegram limits in all sixteen
  locales. Rendering errors no longer imply every API rejection is bad syntax.
- Restored inline-code entities now separate delimiter and content backticks
  and preserve meaningful surrounding spaces.
- Go module and Docker builder use Go 1.26.10. `x/text` moved to v0.41.0 and its
  required `x/sync` to v0.22.0. A patched-toolchain vulnerability scan is clean.

## Telegram findings

Native rich-message formulas already exist. The documented forms are inline
`$...$`, display `$$...$$`, fenced `math`, and HTML `tg-math`/`tg-math-block`.
The expression is raw LaTeX. This is not a documented contract for full KaTeX
compatibility or compiling complete TeX documents. `\(...\)` and `\[...\]`
are not listed delimiters. No automatic delimiter rewriting was added.

Rich output has separate limits: 32,768 text characters including formula
source, 500 blocks, 16 levels of nesting, 50 media attachments, 20 table
columns. These are not a byte limit for Markdown source. Telegram decides
whether a rendered document fits. Arbitrary splitting would damage structures,
so this update does not split or truncate documents.

Cloud `getFile` permits downloads up to 20 MB, with a link valid for at least
one hour. The smaller makeitMD budget is deliberate. A local Bot API server is
not required. `Document` carries the original filename/MIME, which getFile may
not preserve. The existing pinned tg version already implements the required
file and rich-message methods.

## Existing findings that remain open

These precede the file feature. They should be resolved before treating a new
stable release as reliably delivered under failures.

### P1: update retries can repeat a delivered rich reply

`internal/bot/bot.go:256`, `internal/bot/bot.go:302`, `internal/db/store.go:128`.
If Telegram sends successfully and MarkSent fails, the conversion remains
`received`; retrying the update sends again. An ambiguous network failure or
`tg.ErrUnexpectedResult` can take the same path. The transport's restriction on
POST retries does not prevent retries performed by the bot itself.

Next change: persist an attempt before dispatch, distinguish definitely refused
from uncertain delivery, and persist Telegram message IDs/receipts. Uncertain
delivery must not automatically replay a POST. `ErrUnexpectedResult` already
means the API accepted the action and needs its own handling. Exactly-once
delivery cannot be promised across Telegram and PostgreSQL without an API
idempotency key.

### P1: dropped updates can leave retained pending content forever

`internal/bot/bot.go:202`, `internal/db/store.go:245` (`CleanupConversions`).
After retry exhaustion the offset advances, but a conversion can remain
`received`. Cleanup deliberately excludes unresolved rows, and startup has no
pending-row recovery worker. Polling can look healthy while these accumulate.

Next change: explicit retryable, uncertain and terminal outcomes, plus bounded
recovery and operator alerts. A retention-policy change must be documented;
deleting unresolved records silently would violate the current contract.

### P1: pasted-message membership is recalculated on replay

`internal/bot/bot.go:492`, `internal/bot/bot.go:496`.
New neighboring messages can join a conversion whose first update was already
stored or sent. The conflict path returns only status, while the caller uses
the newly grouped source. Source/trace can diverge, or a newly joined message
can be skipped when the old first conversion is already `sent`.

Next change: persist the constituent update IDs and immutable source snapshot;
recover that snapshot, and advance only through updates it owns.

### P2: compatibility fallback can rewrite literal code or formulas

`internal/richmarkdown/normalize.go:24`, called at `internal/bot/bot.go:274`.
Fallback runs after any 400. Its global replacements also see HTML examples
inside fenced code, and blank-line collapsing changes literal blocks. The
first, successful API request is unchanged; this risk is in the retry path.

Next change: protect literal ranges using an established parser, or narrow the
fallback contract. Do not extend the existing regexes into a math parser.
Regression fixture: a rejected document containing fenced `<p>x</p>` must not
deliver a changed code sample after normalization.

### P2: adjacent messages are only a heuristic for a long paste

`internal/bot/bot.go:538` (`samePaste`). Two independent short messages sent
within two seconds may be joined. Joining always inserts a newline, so it is
not a byte-exact reconstruction of an unknown client split.

Next change: make grouping more conservative and test real client behavior.
Files provide the exact-source alternative in this update.

### Shared tg follow-up: redact download HTTP errors centrally

Pinned `tg@v0.0.1-alpha.7/files.go:65` returns parsed non-2xx download responses
without the regular transport's token-redaction step. A proxy could echo a
token-bearing path. makeitMD's new path does not log, store or return these
errors to the polling logger, so it does not expose that payload. The common
library still needs a fix and a regression test for every consumer.

Also move generic idempotent download retries into tg when that library is
updated; makeitMD currently supplies its bounded product retry policy. No tg
checkout or published dependency version was changed by this task.

## Verification and remaining acceptance

Local Go checks use `GOTOOLCHAIN=go1.26.10`, matching the Docker builder:

```sh
go mod verify
go test -race ./...
go vet ./...
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

Tests cover real shared-client HTTP requests against httptest, unchanged math
source, file commands, captions/entities, BOM/CRLF/emoji, binary and encoding
rejection, actual streaming overflow, exact byte-limit acceptance, retries,
cancelled work, cleanup, group silence and terminal replay without a download.

Before release, run a PostgreSQL integration check and live rendering QA on
current Telegram Desktop, Android and iOS. Use `docs/examples/formulas.md` for
fractions, indices, a matrix and Cyrillic context. Also exercise an unknown
LaTeX command, malformed Markdown, a document beyond Telegram's output limits
and a failed download. A successful API response and correct client display
are separate acceptance results. No live Telegram messages, production changes,
release tags or deployments were performed by this task.
